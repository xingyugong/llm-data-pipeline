# LLM Data Pipeline + LoRA Fine-Tuning

A small, honest version of the production LLM fine-tuning workflow:
clean and decontaminate a real instruction dataset, then LoRA fine-tune a
small causal LM on it and evaluate on a held-out split.

## What is real, what is not yet run

- **Real, run 2026-10-28:** the data pipeline on the first 2,000 examples
  of Databricks Dolly 15k (CC BY-SA 3.0, human-written). Result:
  2,000 raw → **1,937 kept** (1,829 train / 108 test). Rejections:
  44 too-short responses, 8 too-long, 3 URLs in responses, 2 PII-like
  patterns, 6 near-duplicates. Split is hash-based on the normalized
  instruction+context, so no split key appears on both sides.
- **Code only, not yet run:** `src/train_lora.py` (LoRA on distilgpt2)
  and `src/evaluate.py`. This VM has no GPU. Do not claim trained-model
  results until training + evaluation have actually been run.
- **No synthetic data.** Every kept example is a real Dolly example that
  survived the filters. Nothing here was generated by an LLM.

## Layout

```
src/clean_data.py   exact + near-duplicate removal, quality filters, hash split
src/train_lora.py   LoRA fine-tune (distilgpt2, r=8) -- run on Colab T4
src/evaluate.py     held-out perplexity + greedy generations, base vs tuned
tests/test_clean.py unit tests for dedup / filters / split
data/processed/     train.jsonl / test.jsonl produced by the pipeline run
reports/            data_quality_report.md from the pipeline run
```

## Run the data pipeline

```bash
pip install -r requirements.txt
python -m src.clean_data --limit 2000 --out-dir data/processed \
    --report reports/data_quality_report.md
pytest tests -q
```

## Run training (Colab T4, free GPU)

```bash
pip install torch transformers peft accelerate datasets
python -m src.train_lora --data data/processed/train.jsonl \
    --output-dir outputs/lora-distilgpt2 --max-examples 2000 --epochs 2
python -m src.evaluate --adapter outputs/lora-distilgpt2 \
    --test data/processed/test.jsonl --out reports/evaluation.md
```

For a full run, re-run the pipeline with `--limit 15011` (the whole
Dolly set) before training.

## Why this shape

Data engineering for LLMs is mostly this: dedup, quality filtering,
PII removal, and leakage-free splits -- the model code is the short part.
The filters here are deliberately simple and inspectable (exact hash,
shingle Jaccard ≥ 0.85, length/language/PII rules) so each rejection can
be explained, rather than hidden inside a black-box cleaner.

## Limitations

- distilgpt2 is a 2020-era 82M model; results do not transfer directly
  to modern 7B+ instruction models, but the pipeline and LoRA mechanics do.
- Dolly is general instruction data, not economics-specific; a domain
  follow-up would swap in a licensed economics/QA source with the same
  cleaning code.
- Near-duplicate detection is pairwise-greedy and O(n²) in the worst
  case; it is fine at 15k examples and would need MinHash/LSH at scale.
